给 AI 助手一本靠得住的账

快速上手 · 五分钟看懂这是什么、怎么用

你的 AI 助手（聊天机器人、智能家居管家、客服 Agent）有两个先天毛病： 记不住，和记住了也改不对。这个项目就是替它管记忆的后端服务—— 把 Agent 听到的每件事记成一笔一笔的账：谁说的、什么时候说的、 后来有没有改口。改口不覆盖，划掉旧的记上新的；要它忘，也只是划线，账本永不撕页。

它给 Agent 的四个本事WHAT IT GIVES YOU

壹记得住

一句话丢进来，自动抽出事实落账，附上出处和两个时间戳。

贰改得对

用户改口时自动对账：判矛盾、关旧账、记新账，全程留痕。

叁忘得掉

说"忘了吧"就软遗忘——划掉这一行，但随时可以审计当时删了什么。

肆翻得回

"上周三我们以为温度是多少？"——按时间点回放当时的记忆状态。

三步用起来HOW TO USE

下面每个请求都是刚在真实服务上跑通的，可以直接复制。所有请求都要带请求头 Authorization: Bearer <你的key>。

1记 —— 把一句话丢给它

Agent 听到用户说话，把原文丢给 process，系统自己抽事实、对账、落库：

POST /v1/memories/process 
{
  "text": "阳台的温度是19度",
  "source_id": "voice-msg-001"
}
返回（节选） 
{
  "created": ["fccd730a-…"],
  "relations": [
    { "subject_id": "阳台", "predicate": "temperature_preference",
      "relation": "CREATED" }
  ]
}

用户改口再说"阳台的温度是20度"，返回的 relation 会变成 CONTRADICTION、旧账 id 出现在 replaced 里——旧账自动关闭，新账生效，两笔都在。

2问 —— 三种问法

问某个东西（关于主卧都知道什么）：

GET /v1/memories?subject_id=主卧


模糊地问（关键词命中主体、谓词、内容）：


POST /v1/search

{ "query": "主卧", "limit": 5 }


回到过去问（上周三当时以为的是什么）：


GET /v1/memories?subject_id=主卧&known_at=2026-11-05T00:00:00Z


翻旧账时加 include_superseded=true 能连被划掉的历史一起看——这就是审计视图。



3忘 —— 划掉，但不撕页


DELETE /v1/memories?subject_id=阳台&predicate=temperature_preference


返回

{ "forgotten": ["4e1ac829-…"], "count": 1, "audit_retained": true }


被遗忘的账不会消失：在 /v1/events 事件流里永远查得到"何时删了什么"，
这正是和普通数据库 DELETE 的本质区别。
